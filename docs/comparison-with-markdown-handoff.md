# 手動 Markdown handoff 方式との比較（Phase 0）

[claude-code-agent-workflow](https://github.com/0x000x7f/claude-code-agent-workflow) の
`/handoff` 方式（人間が HANDOFF 文書を運搬）と、本プロジェクトの MCP bridge 方式の比較。

## 比較表

| 観点 | Markdown handoff（手動） | MCP bridge（本プロジェクト） |
|---|---|---|
| セットアップコスト | ゼロ（文書を生成してコピーするだけ） | MCP server の導入・設定が必要 |
| 自動化度 | 低（運搬・貼り付け・回収が手動） | 高（生成→実行→検収が1フロー） |
| 安全性 | 高（人間が運搬のたびに内容を目視する） | 設計依存（承認ゲート・workspace guard で担保する必要） |
| 監査性 | 高（文書がそのまま記録になる） | 中（実行ログの設計が必要） |
| ツール非依存性 | 高（Codex / Cursor / 人間、誰にでも渡せる） | 低（Codex CLI 専用のブリッジ） |
| 失敗時の影響 | 小（文書を渡し直すだけ） | 中（サブプロセス・部分適用の後始末が必要） |
| usage limit 対策 | 手動で切り替え | 自動切り替えの判断材料を設計可能（未解決論点） |

## 結論

1. **handoff 方式は廃止しない。** ブリッジが不調・未導入・対象ツールが Codex 以外の場合の
   **フォールバックとして維持**する。HANDOFF 文書フォーマット自体は両方式で共通であり、
   ブリッジは「運搬の自動化」だけを担う
2. MCP bridge が優位なのは、**同種のハンドオフを高頻度に回す**運用
   （例: 多数の小 Phase を Codex に流し続ける）に達した場合
3. したがって導入判断の基準は「handoff の往復回数が手動運搬のコストを上回るか」であり、
   低頻度のうちは手動方式で十分

## 設計への含意

- ブリッジの入力は HANDOFF 文書**そのもの**とする（独自フォーマットを作らない）。
  これにより両方式の互換性が保たれ、いつでも手動方式に戻れる
- ブリッジが落ちても運用が止まらないことを、設計上の成功条件に含める
